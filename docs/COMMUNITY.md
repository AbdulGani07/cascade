# Community operations

## Proposed Discussions categories

An owner may enable GitHub Discussions and configure:

- **Announcements** — maintainer-only project and release news.
- **General** — community topics that do not fit a more specific category.
- **Ideas** — early product or workflow proposals before an actionable issue exists.
- **Q&A** — installation, configuration, plugin, and usage questions.
- **Show and tell** — demonstrations of Cascade reports, integrations, and workflows using
  non-sensitive examples.
- **Language plugins** — parser, resolver, fixture, and ecosystem design discussion.
- **Architecture policies** — governance-rule patterns and architecture-analysis practices.

Discussions must not receive vulnerability reports or proprietary source. Enabling Discussions and
setting answer/announcement permissions remain manual owner actions.

## Triage process

New reports should be checked for sensitive content, reproduction detail, scope, duplicates, and the
correct support channel. Apply `good first issue` and `help wanted` only under the criteria in
[Governance](GOVERNANCE.md). Candidate drafts are maintained in
[`contributing/good-first-issue-candidates`](contributing/good-first-issue-candidates/README.md);
they are proposals for owner review, not published issues.
